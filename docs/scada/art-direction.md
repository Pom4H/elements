# SCADA visual art direction

This document intentionally comes before another SVG rewrite.

The project has already proved the runtime model: attributes, derived states, ports, motion and interchangeable SVG representations are tractable. The remaining problem is visual authorship. We will not treat technical correctness as evidence of good design.

## Reference corpus

The visual direction is derived from recurring ideas across several independent systems rather than copied from a single library.

### ABB high-performance HMI

Reference: https://library.e.abb.com/public/d62da22416d94dbf9b60a4dd3efc1471/8VZZ000576T0000_High_Performance_HMI_WP_v3.pdf

Useful rules:

- normal process graphics are predominantly neutral / grayscale;
- alarm-priority colours are reserved for alarms;
- unnecessary colour, shape and motion reduce operator focus;
- abnormal conditions must visually dominate normal equipment;
- normal operating ranges and limits should be available near the process value.

### Emerson high-performance operator displays

Reference: https://www.emerson.com/is/content/emerson/en/corporate/shared-assets/documents/pws_008400-high-performance-control-room-operator-display-services.pdf

Useful rules:

- overview graphics show information needed for normal monitoring;
- startup, shutdown and troubleshooting detail belongs to drill-down layers;
- high performance is not equivalent to literal grayscale: low-salience colours may be used deliberately.

### Ignition Perspective Symbols

References:

- https://docs.inductiveautomation.com/docs/8.1/appendix/components/perspective-components/perspective-symbols-palette/perspective-pump
- https://docs.inductiveautomation.com/docs/8.3/appendix/components/perspective-components/perspective-symbols-palette/perspective-valve
- https://docs.inductiveautomation.com/docs/8.3/appendix/components/perspective-components/perspective-symbols-palette/perspective-motor
- https://docs.inductiveautomation.com/docs/8.3/appendix/components/perspective-components/perspective-symbols-palette/perspective-vessel

Important architectural confirmation: one symbol contract can expose several visual appearances. Perspective uses `p&id`, `mimic` and `simple` appearances while preserving the component model.

### Open HP-HMI symbol library

Reference: https://github.com/jsgorana/node-red-dashboard-2-scada-kit
License: Apache-2.0.

The hand-authored SVG catalog uses compact industrial silhouettes, stable bindable parts, explicit state text and separate alarm shapes. We study its geometry and state separation but do not make it our visual identity.

### FUXA / JSON-SCADA

References:

- https://github.com/frangoteam/FUXA
- https://github.com/frangoteam/FUXA-SVG-Widgets
- https://github.com/riclolsen/json-scada

The important lesson is workflow: serious SCADA users repeatedly need reusable SVG objects with stable bindings, and successful systems let the SVG remain a first-class authored graphic rather than forcing every shape to be generated by runtime code.

## Seed set

Do not expand the library until these five look unquestionably related:

1. centrifugal pump
2. vertical vessel / tank
3. isolation valve
4. control valve
5. three-phase motor

These cover rotating equipment, stored process media, binary flow control, modulating control and electrical/mechanical equipment.

## Visual DNA

### Silhouette first

At 64–96 px the object must remain recognisable with labels hidden.

If recognition depends on fins, bolts, terminal blocks, gradients or internal cutaways, the drawing is too detailed.

### One optical scale

Seed elements use a common nominal drawing box and comparable visual mass. Physical size differences may exist in a scene, but one family must not look three times more detailed than another.

### Line system

- primary equipment outline: one shared weight;
- internal mechanical line: roughly 60–70% of primary;
- process/electrical connection stub: same family as primary outline;
- no decorative hairlines;
- rounded joins only where they describe actual rounded construction, not as a generic icon style.

### Materials

Normal equipment is neutral. Use at most three neutral material tones:

- primary body;
- secondary fitting / end cap;
- interior / panel.

No gradients, glows, chrome or fake 3D in the main SCADA representation.

### Operation

Running/open/active is not an alarm and must not repaint the whole device.

Preferred indication:

- one low-salience blue operation marker;
- optional small mechanical motion when motion communicates something useful;
- optional explicit text such as RUN / OPEN when ambiguity matters.

### Warning and alarm

Severity is an attention layer, not a material.

Preferred approach:

- equipment silhouette stays neutral;
- warning adds an amber attention badge;
- alarm adds a red attention badge;
- the badge sits outside the primary silhouette so state cannot be confused with equipment material;
- use shape + colour, never colour alone.

### Process media

Process colour is allowed where it represents the process itself: vessel level, a small flow indication, temperature band, etc. It must not become the equipment body colour.

### Typography

- tag is the strongest text;
- primary value is secondary but immediately readable;
- engineering metadata is tertiary;
- use one compact type scale across all equipment;
- do not put prose inside the SVG silhouette.

### Labels and values

The visual hierarchy is stable even when geometry changes:

`tag → primary value → operation/severity → quality`

Do not invent a different label grammar for every element.

## Representation model

Only after the main SCADA drawing is accepted do we derive the other representations.

### `flat`

The master representation.

- best operator readability;
- neutral industrial silhouette;
- minimal live values;
- no decorative realism.

### `pid`

Derived from the same visual DNA but notation-first.

- standard engineering symbol geometry;
- tag remains available;
- no SCADA readout chrome;
- no physical details that do not belong in a P&ID.

### `equipment`

Derived from `flat`, not designed independently.

- adds only the large physical features useful at close zoom;
- may show motor body, actuator, yoke, nozzles, feet or terminal enclosure;
- still uses the same line/material/state grammar;
- never becomes a product rendering.

## Seed-03 direction

The current visual study uses:

- neutral body and fittings;
- dark neutral engineering outline;
- desaturated blue operation marker;
- explicit amber/red attention badges;
- blue process fill only where it describes media;
- no warning/alarm recolouring of the complete device;
- a 64–96 px silhouette check alongside the full-size drawing.

This is a direction, not yet a production asset.

## Review questions

Before an SVG becomes a runtime element, answer all of these by looking at it:

1. With labels hidden, is the equipment recognisable at 96 px?
2. Does it look like the same library as the other four seeds?
3. Is any normal-state colour competing with warning/alarm?
4. Is there geometry whose only purpose is to make the object look more expensive or realistic?
5. Does removing 20% of the geometry make the object better? If yes, remove it.
6. Does the object remain readable beside pipes, labels and neighbouring equipment in a real process scene?
7. Can warning/alarm be noticed without changing the equipment's identity?
8. Is motion conveying process state, rather than merely making the screen feel alive?

Only after the five seeds pass these questions should the grammar be scaled to compressors, fans, heat exchangers, PLCs, drives and electrical equipment.
